📘 Manual — Prospector de Sites

Versão 2.3.0

Este plugin acha clientes no Google Maps, cria/refaz o site com padrão profissional, publica no Cloudflare e leva a proposta até o cliente — e você administra tudo num painel (CRM) que roda no seu computador, de graça. Funciona em 2 modos (você escolhe num popup ao prospectar): Redesign (quem tem site ruim) e Criar site (quem não tem site).

Neste manual:
1. O que você precisa antes · 2. Configuração (uma vez só) · 3. Os 2 modos · 4. O ciclo completo · 5. Publicação automática · 6. O dashboard (CRM) · 7. E no Mac? · 8. Problemas comuns

1. O que você precisa antes

  • Claude Cowork (app do Claude pra desktop) com este plugin instalado.
  • Extensão Claude in Chrome conectada — é ela que navega no Google Maps.
  • Conector do Gmail ativo (Configurações → Conectores) — rascunhos de proposta e leitura de respostas.
  • Conector do Google Drive — planilha de leads no Google Sheets.
  • Conta no GitHub + Cloudflare Pages (as duas grátis) e o git instalado e autenticado na máquina — é por aqui que os sites são publicados.
  • Uma pasta conectada no Cowork (ex.: "Clientes") — tudo fica salvo nela.

2. Configuração (uma vez só)

  1. Digite /setup no Cowork e responda: sua assinatura (nome, apresentação, WhatsApp), nichos preferidos, cidade e quantos leads por busca.
  2. Conexão Cloudflare: no dashboard, nada de senha no chat. Crie um repositório vazio no GitHub só pros clientes (ex.: prospector-sites) e conecte-o a um projeto do Cloudflare Pages (Workers & Pages → Create → Pages → Connect to Git, sem build command). Depois, no dashboard (iniciar-dashboard.bat) → aba Configurações → seção Conexão Cloudflare → preencha o repo, o projeto e o subdomínio .pages.dev → Salvar conexão. Não há senha: o git usa as credenciais já salvas na sua máquina.
  3. O Claude faz um teste de publicação e te entrega este manual + o dashboard prontos na pasta.
💡 Preencha também seus dados de contratante na aba Configurações do dashboard — todo contrato já sai com eles.

3. Os 2 modos (você escolhe num popup)

Ao rodar /prospectar, o Claude abre um popup pra você escolher o modo da rodada. Cada lead fica marcado com o modo (aparece no card do dashboard) e os comandos seguintes se adaptam sozinhos.

🔄 Redesign✨ Criar site
AlvoFatura bem + site próprio ruimFatura bem + sem site (só Instagram/WhatsApp)
De onde vem o conteúdoDo site atual do clienteDo Instagram do cliente
Como abordaE-mail (com a capa antes/depois)Texto de WhatsApp / DM, 1 a 1
PrecisaE-mail público do leadWhatsApp ou @Instagram do lead
💡 Regra prática: cidade grande e mercado consolidado costumam ter mais Redesign. Cidade pequena/turística (muito negócio forte só no Instagram) rende mais no Criar site.

4. O ciclo completo (6 passos + 3 automáticos)

ComandoO que faz
/prospectarAbre o popup de modo e varre o Google Maps por negócios nota ≥ 4.7 com muitas avaliações. Redesign: com site ruim + e-mail. Criar site: sem site + Instagram/WhatsApp. Gera planilha + alimenta o dashboard.
/redesenharCria as páginas dos melhores leads (5+ por lote) com fotos e logo REAIS — do site (Redesign) ou do Instagram (Criar site). Entrega: página + editor visual + comparador.
/editorQuer mexer em texto ou foto? Abre a versão editável no navegador — clica, edita, exporta.
/publicarSobe página + capa de apresentação no Cloudflare Pages (git push) e valida o HTTPS (cadeado).
/propostaRedesign: escreve o e-mail (elogio + defeito + link da capa), checklist anti-spam, rascunho no Gmail. Criar site: monta o texto de WhatsApp/DM pronto pra você colar.
/respostasLê o Gmail e move sozinho no painel quem respondeu. Dica: peça pro Claude agendar todo dia às 9h.
/followup3+ dias sem resposta? Gera o lembrete gentil (1 por cliente, nunca repete).
/contratoFechou? Gera o contrato em folha imprimível + Word travado (cliente só preenche onde você deixou) e o rascunho no Gmail.
⚠️ A regra de ouro (nos 2 modos): nada é inventado. Serviços, credenciais e fotos vêm do cliente real — do site (Redesign) ou do Instagram (Criar site). O texto é reescrito com técnica, dizendo a mesma verdade.

5. Publicação automática — git push, build sozinho

Depois da conexão Cloudflare configurada (passo 2 acima), publicar é um comando só:

  1. Rode /publicar. O Claude copia a página e a capa de cada cliente pro clone local do repo (sites-publicados/[slug]/) e faz git push.
  2. O Cloudflare Pages detecta o push e faz o build automático em segundos — sem FTP, sem senha, sem script na sua máquina.
  3. O Claude confere as URLs https://[subdomínio].pages.dev/[slug]/ e o cadeado HTTPS na sequência.

O deploy roda direto do agente por HTTPS — nada pra clicar. Só precisa do git autenticado uma vez na máquina.

💡 Deu 404 logo após publicar? É o build ainda rodando. Espere ~30s e recarregue — o Cloudflare já serve HTTPS válido por padrão.

6. O dashboard (seu CRM local)

Dê dois cliques em iniciar-dashboard.bat na sua pasta (precisa de Python instalado) — abre em http://localhost:8765 com tudo salvo no banco prospector.db. Sem Python, abra dashboard.html direto (modo leitura com edições locais).

  • Visão geral — números do funil e receita.
  • Pipeline — kanban: arraste o card conforme o cliente avança. Ao soltar em "Fechado", informe o valor — a receita soma na hora.
  • Clientes — tabela com busca, edição (✎) e exclusão.
  • Sites — preview de cada página criada, com botões de abrir/editar.
  • Comparador — antes/depois lado a lado de cada cliente, dentro do painel.
  • Follow-ups — quem está parado há dias, com alerta laranja.
  • Contratos — ver a folha, imprimir, baixar o Word travado, marcar assinado.
  • Financeiro — recebido, a receber, MRR das manutenções e projeção 12 meses.
  • Configurações — seus dados de contratante + conexão Cloudflare (repo, projeto Pages e subdomínio; preencha uma vez, sem senha).

7. E no Mac?

Tudo funciona igual — só muda o arquivo de clique duplo do painel: iniciar-dashboard.command. A publicação não depende de sistema: é git push direto do agente. O /setup entrega o arquivo certo pro seu sistema.

💡 Na primeira abertura o macOS pode bloquear por segurança: clique com o botão direito no arquivo → Abrir → Abrir. Só na primeira vez. Python 3: se não tiver, brew install python3 ou python.org.

8. Problemas comuns

O comparador não apareceu depois do /redesenhar

Peça: "gere o comparar.html e atualize o dashboard". A partir da v0.11.1 a entrega é travada e ele sempre vem — e também fica na aba Comparador do dashboard.

O /publicar falha no git push (pede login ou dá erro de autenticação)

O git não está autenticado na máquina. Faça um git push qualquer no repo de sites uma vez (ou logue pelo credential manager / GitHub CLI) pra salvar as credenciais — depois o /publicar sobe sozinho. Confira também se o repo e o subdomínio estão certos em Configurações → Conexão Cloudflare.

Quero um domínio próprio no lugar do .pages.dev

O subdomínio .pages.dev já é limpo e apresentável, pode enviar pros clientes. Se quiser um domínio próprio, aponte-o no Cloudflare Pages (projeto → Custom domains) e atualize o campo subdomínio nas Configurações do dashboard.

Meu e-mail pode cair no spam?

A checklist anti-spam do /proposta existe pra isso: 1 link só, sem palavras de vendedor, sem anexo, assunto-pergunta personalizado, envio 1 a 1 da sua conta. Mantenha poucos envios por dia — padrão humano.

O lado "Antes" do comparador fica em branco

Alguns sites antigos bloqueiam visualização embutida. Use o link "abrir ↗" no cabeçalho da coluna.

O dashboard diz "modo arquivo"

Você abriu o dashboard.html direto. Pra salvar no banco, abra pelo iniciar-dashboard.bat (requer Python: python.org/downloads, marque "Add to PATH").

Lead sem e-mail?

O plugin descarta e busca outro — proposta vai por e-mail. Pros descartados com WhatsApp, peça o texto adaptado pro zap.
